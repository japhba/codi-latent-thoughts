# Training provenance

The measurements use the published final CODI checkpoint, not freshly trained weights. Its revision and weight hash are in `manifest.json`. The original checkpoint's five-epoch recipe is recorded in `codi_qwen3_8b.yaml`: Qwen3-8B, GSM8k-Aug-NL plus CommonsenseQA, LoRA rank 128 / alpha 32, six thoughts, projection width 4096, effective batch 256, learning rate 2e-4, seed 11. The recovered source's default distillation criterion is SmoothL1, with reference-state standard-deviation normalization; an earlier model card calling it simply MSE is imprecise.

`codi_qwen3.patch` holds our changes to the CODI training code (`train.py`, `src/model.py`, `src/datasets.py`: Qwen3-8B support and a filler-latent control). Apply it to [cywinski/codi](https://github.com/cywinski/codi) at `f0bf2fa` (`git apply training/codi_qwen3.patch` in that checkout). It reproduces the recovered source snapshot, which includes later local edits, rather than a pristine snapshot of the original training date. The config fixes `push_to_hub: false` and has no warmstart. It records the training recipe; exact repeat training is not certified. The upstream config included epoch-only saves. This provenance file retains that schedule and should be updated to periodic full resume checkpoints and regular evaluations before commissioning a new long run. No new training is launched by the reproduction CLI.

The readers are two separate NLA runs, fixed to their step-3200 adapters. The original data are CODI-correct captures from the training/augmentation corpus, one vector per row, six positions per problem. Vector injection is a norm-matched additive hook after actor block index 1; it is not input-embedding replacement. The recovered trainer normalizes target and reconstructed activations when computing reconstruction FVE, so the recorded curves concern directions. The stored FVE excludes generations with reward at or below the trainer's -2 validity cutoff.

`nla_z_historical.yaml` and `nla_h24_historical.yaml` are exact recovered final-phase configurations, including original path strings. They document a continuation from step 1600 to 3200. `start_step` and `resume_from_lora` must both be reset to reproduce a run from warmstart; substitute paths to the pinned AV, AR, full RL parquets, and a local output directory. The reference settings are batch_prompts=256, group_size=8, lr=1e-4, critic_lr=8e-5, kl_beta=0.01, z_dropout=0.1, r=128, alpha=16, rsLoRA, eval_every=10, save_every=4, state_save_every=20. Validation is split by document hash, keeping all six positions together. The historical YAML's max_rows values differ because the correct-row corpora differ.

The pinned EasyNLA implementation is bundled under `vendor/EasyNLA`, with its MIT license and source provenance. The original runner was the self-contained vLLM trainer; vLLM was a separate runtime. Its public package documentation pins vLLM 0.19.0, but the precise installed rollout environment was not recovered. Running the bundled source requires that additional setup and enough GPUs for actor, critic, and rollouts. This package does not silently install or guess that runtime.

The exact **evaluation** activation subsets are bundled. The full RL parquets and original full capture arrays are not part of this package; the arrays were not recovered. Consequently exact retraining and recomputing every historical FVE evaluation from weights are unavailable here. The histories themselves reproduce exactly. Recreating a training corpus from the same pinned organism and public augmented questions is possible, but may select a different correct-row population and cannot be called an exact replication of these readers.

This is a provenance recipe and recovered implementation, not a tested end-to-end training launch. The tested reproduction scope and remaining assets are stated in `../README.md`.
