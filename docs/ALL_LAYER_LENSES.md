# Dedicated layer lenses and pooled readouts

The current curve references use a new calibration of 36 separate full 4096×4096 Jacobian matrices: one for the projected input state h0 and one for each pre-final residual state h1–h35. h36 is already final-normalized and goes directly to the vocabulary head in both methods; it has no transport to learn. Computing every source gradient together shares backward passes, but each layer has its own independently accumulated matrix. This is analytic Jacobian calibration, not optimizer-based training.

Every stage uses the pinned CODI checkpoint-7580 in manifest.json. Calibration and convergence validation use **raw question + EOS + BOT**, matching the reader-capture prompt. Calibration candidates are the bundled GSM8k-Aug-NL training questions 4000–4799; validation candidates are 4800–4999. The first 96 and 24 respectively with a correct freshly generated CODI answer are captured. Both sets are disjoint from all 156 unique blog evaluation questions. The calibration may stop before 96 examples under the convergence rule below. Accepted indices and complete questions are saved.

## Estimator and normalization

For each calibration problem, CODI first generates its six projected thought inputs. A teacher-forced replay holds those six input vectors fixed. The target is the final block output **before** final RMSNorm. For each output coordinate, the cotangent sums all target positions from BOT through thought six. Causality leaves only present/future targets for each source. The returned source gradients are averaged over BOT and the six thought positions for residual states, and over the six thought positions for h0. Exact Jacobians are then averaged across calibration problems. The reduction follows the [Jacobian-lens reference implementation](https://github.com/anthropics/jacobian-lens/blob/main/jlens/fitting.py), with valid positions restricted to the latent rollout. This retains the historical estimator's reduction and source conventions; it does not differentiate the recursive projection/feedback path.

J-lens uses row-vector multiplication `h @ J.T`, then the checkpoint's final RMSNorm once, then its vocabulary head. LogitLens uses the same norm and head directly. Both use the normalized h36 state directly with no second norm. Readouts use float32 and disable TF32. All 36 matrix fingerprints are recorded and required to differ. The shared h36 outputs must agree exactly; other layers are evaluated independently.

## Progress and resumption

Full estimator sums, completed-problem count, the cursor within a partially computed Jacobian, accepted data order, Torch CPU/CUDA RNG states, convergence history and elapsed time are checkpointed. There is no optimizer or LR scheduler in this estimator. Local checkpoints are written atomically; a copy is transferred atomically to shared storage at least every 120 seconds and at each evaluation. Resume restores a complete estimator state, including partial rows, rather than restarting the current problem or averaging it twice.

Every eight calibration examples, the fit measures the first-answer-token cross-entropy and top-one accuracy at every fitted source over six positions. The fixed training diagnostic uses the first eight calibration examples; the independent validation diagnostic uses 24 correct rollouts. These are **convergence proxies**, not the blog's complete-value mention scores. The mean CE curves use logarithmic axes. After at least 32 calibration examples, fitting stops when both proxy CE slopes have absolute value below 0.01 in log-loss versus log-example-count over the last four evaluations. Otherwise it finishes at 96. Nonfinite gradients, metrics, and replay disagreement fail loudly. The small numerical test checks the reduction and recovers identical matrices after splitting the output-coordinate calculation at a resume boundary.

W&B run/group `jl4` records the calibration curves. The saved `layer_lens_fit.json` and `layer_lens_fit.png` record the actual accepted count, stop reason and history.

## Pooled scoring

For the **Appendix E skyline**, each method contributes its five token alternatives at **all 37 states and all six thought positions**: 222 independent readouts, up to 1,110 candidate tokens per problem. There is no location selection. The compact figures restrict this same evidence to the reader's source layers: h24 or z for NLA, and h9/h18/h27/h35/h36/z or z alone for AO. They retain all six thought positions. `CURVE_BASELINES.md` lists the exact budgets and both sets of scores. Complete values must be expressed within one individual token; alternatives from different positions, layers or top-five ranks are never concatenated. This is token-candidate coverage, not autoregressive answer generation or a theoretical ceiling on decodability.

A token's allowed meaning is self-contained under this criterion. To avoid repeatedly judging the same candidate, we deduplicate candidate strings globally. Exact numeric literals are parsed deterministically. Remaining distinct strings are shown to the original Gemini judge in batches of independent alternatives, without questions, labels, layer/position names or method identifiers. The prompt is the previous gold-blind EXTRACTION_PROMPT; responses use strict structured JSON, cite exact candidate strings, and are saved in full. Existing gold-independent token-meaning audit rules and the saved fresh 31-token review are applied uniformly. The review excludes incomplete words and code fragments, corrects a false-negative complete cardinal, and preserves literal cardinal readings of polysemous phrases. Raw extraction responses remain untouched. Each problem's pooled values are the union of meanings explicitly extracted from its own candidates. Answers and eligible non-answer intermediates are matched by deterministic exact gold intersection. The recorded semantic label-permutation expectation uses the same extracted value sets and the same cohort label frequencies. Broader pools can increase accidental value coverage, so this expectation is reported alongside matches.

Evaluation captures retain the exact historical h24 and projected-input vectors at their corresponding locations. Other locations are freshly captured with an unpadded single-problem prompt and a valid KV cache. The h24/z replay agreement is recorded. Each NLA curve reference uses its own original 60-question cohort; the AO references use its original 48 questions. Every baseline and skyline matches its corresponding reader's questions. The h24 and z question sets were independently selected by the historical scan and overlap on only 12 questions; this limits comparisons between those reader curves. The selection code and question lists are recorded in `curve_evaluation_protocol.json`. Compact references match reader layers while retaining all-six-position access; NLA histories read only thought one. Appendix skylines receive all layers. Original reader answer parsers and histories remain unchanged; semantic lens answer mentions are a different criterion from answer-generation accuracy. No faithful-computation or causal-steerability conclusion follows from candidate-value coverage alone.

## Reproduction

From this directory, install locked GPU/training/judge dependencies into a local environment using the normal UV_PROJECT_ENVIRONMENT convention. Keep all model files, activation captures and matrix/resume files outside NFS home. The CLI takes explicit paths and needs no authoring-checkout files:

~~~bash
python -m codi_repro.all_layers capture --cache-dir /path/to/cache --out /path/to/local-run
python -m codi_repro.all_layers fit --cache-dir /path/to/cache --out /path/to/local-run --shared /path/to/shared-run --dim-batch 32 --group jl4
python -m codi_repro.all_layers fit --cache-dir /path/to/cache --out /path/to/local-run --shared /path/to/shared-run --dim-batch 32 --group jl4 --resume
python -m codi_repro.all_layers readouts --cache-dir /path/to/cache --out /path/to/local-run
python -m codi_repro.all_layer_analysis --readouts /path/to/local-run/all_layer_lens_readouts.json --out /path/to/judge-run
python -m codi_repro.lens_topk --organism-dir /path/to/checkpoint-7580 --cache-dir /path/to/cache --jacobians /path/to/local-run/layer_jacobians.pt --out /path/to/topk
~~~

`lens_topk` writes the top-100 tokens behind `lens_topk_chance.png` and fails unless its top-five lists agree with the bundled readouts (top-1 and top-5 overlap above 0.9). The first `fit` call starts a calibration; only a restart uses `--resume`. `all_layer_analysis` stops when the judge cites a candidate outside its batch; rerunning with `--resume` keeps the completed batches. See [RERUNS.md](RERUNS.md) for downloading `/path/to/checkpoint-7580`.

`--organism-dir /path/to/checkpoint-7580` optionally uses an existing checkpoint and verifies its fingerprint. Without it the pinned authenticated HF snapshot is downloaded. If moving nodes, rerun deterministic capture first or copy the captured arrays and question lists to the new local run directory, then resume from shared storage. Use a new three-character W&B group for a new commissioned experiment batch. The SLURM launcher is an execution artifact outside version control.

To reproduce new scores offline, place the saved readouts, calibration/capture metadata, extraction dictionary and deterministically derived verdicts into the corresponding artifacts/ filenames in a working copy. The published companion includes this compact evidence. The 2.4 GB matrices and larger activation arrays are fingerprinted execution artifacts; offline scoring needs neither them nor the model or an API key. `python -m codi_repro reproduce` regenerates the four original curve figures, layer profile and calibration curves from the bundled records. All previous lens evidence remains available as explicitly historical measurements.

The exact executed fit source is preserved as `artifacts/all_layer_fit_source.py` with its runtime fingerprint. The maintained fitter additionally checks replay before row iteration, allowing resume when the final row was saved just before the completed-problem counter advanced. This changes only that interruption boundary; the estimator and readout mathematics are unchanged.

The completed run also passes a full-checkpoint GPU resume regression. From this directory, `PYTHONPATH="$PWD" python tests/check_full_checkpoint_resume.py --source /path/to/completed-run --out /path/to/new-local-check --shared /path/to/new-shared-check --cache-dir /path/to/cache --group jl4` rewinds the last-example counter while retaining all its completed rows, resumes, and requires exact equality of every resulting matrix. It uses offline W&B and leaves the source run untouched. The saved validation result is bundled.
